# Implementation Plan — `locate-test`

Порядок задач = зависимость: задача N опирается на всё до неё, если не сказано иное. Маркеров `(P)` нет: чистая логика
живёт в одном модуле, а все правки компонента идут в один живой `.toe` через один инстанс TD — общий изменяемый ресурс.
Каждая подзадача заканчивается «чем проверено»: pytest, `td_get_errors`, перехват байт в байт или замер (правило проекта
«готово — только с фактом проверки»). Правки `.toe` — только через twozero; `td_get_hints('bootstrap')` в начале сессии;
сохранение — `safe_save`; стенды `/project1/stage0` и `/project1/stand/spike*` не трогаются. Задача 7 — документация:
правила генерации её исключают, но требование 12.5 обязывает; оставлена проверяемая часть (режим `docs`, контрольная точка).

- [ ] 4. Расширение Locate
- [ ] 4.1 Цель, режимы, поведение остальных и события
  - Команда цели: разбор → одна запись таблицы на фикстуру → униформы → снятие обхода шейдера → строки `info` → `onLocate`
    один раз; ошибка цели — прежнее состояние, сообщение в `info` и `onOutputError`; снятие — обход шейдера
  - Пары режима, остальных, уровня, приглушения, мигания, бега меняют только униформы
  - Сообщения в `info`: пропущенные фикстуры цели, «номер не помещается», «вывод выключен» при выключенном выводе компонента
  - Шаблон колбэка `onLocate` в колбэках по умолчанию
  - Готово: в TD команды по `id`, номеру, имени, группе, выходу и порту зажигают нужные точки на выходе `hook`; ошибочная цель
    не меняет вывод и даёт сообщение; `onLocate` вызывается один раз на смену; при смене цели реплики движка не пересоздаются
    (пути и ID узлов прежние), `totalCooks` таблиц движка и `engine/pts_cells` не растёт; строки `info` Locate живут дольше
    тика счётчиков
