# Research & Design Decisions — `locate-test`

## Summary
- **Feature**: `locate-test`
- **Discovery Scope**: Extension (лёгкое исследование): компонент `dsm` (`pixel-engine` 0.1) уже даёт точку `hook`,
  вывод по группам, автоперезагрузку; ядро `patch-core` — группы, порты, `set_acceptance`, `fix_reversed`, `save`.
- **Key Findings**:
  - Подсветку цели можно считать одним `glslPOP` внутри `hook`: атрибуты ячейки `fx`, `cell`, `active`, `Color`
    уже есть, данные на фикстуру приходят массивом из CHOP (`texturebuffer`), время — униформой.
  - `dmxoutPOP` при двух источниках в одних каналах юниверса берёт **последний в списке** `fixture`, а не больший
    байт (опыт `/project1/stand/spike_raw`). Сырой адрес — отдельная фикстура на весь юниверс, последней в списке.
  - Запись статуса приёмки не должна пересобирать движок: автоперезагрузка по дате файла пересоздаёт реплики
    (0,3–1 с на 14–50 тыс. ячеек). Нужен путь «записать патч без пересборки» в расширении движка.

## Research Log

### Точка подключения `hook` и атрибуты ячейки
- **Context**: требования 2–4, 6 — подменять цвет ячеек по цели и режиму без пересборки геометрии (10.4).
- **Sources Consulted**: `docs/engine.md` (контракт `hook`), `src/td/dsm_geometry.py` (`CELL_COLUMNS`),
  `td_get_par_info('glslPOP')` на TD 2025.33070.
- **Findings**:
  - Точки в `hook`: `P`, `Tex`, `Color` (float4, альфа 0), `fx` (индекс фикстуры в патче), `cell` (`data_index`, порядок
    по проводу с учётом `direction` и `cell_offset`), `prof`, `dgrp`, `ogrp`, `active`, `bright`, `col`, `mute`.
  - `glslPOP`: страница Arrays — массив из CHOP типа `uniformarray` или `texturebuffer`; `outputaccess = readwrite`
    позволяет читать и писать `Color` на месте; страница Vectors — униформы с выражениями.
  - Униформ-массивы читают **сэмплы**, не каналы (мануал twozero, правило 14): таблица на фикстуру — 1 канал × N сэмплов
    на компонент или `vec4` из 4 каналов × N сэмплов.
- **Implications**: один шейдер `locate.glsl` в `hook`; таблица на фикстуру (`locate_fx`) пишется Python при смене цели;
  в остальное время шейдер стоит в обходе (`bypass`) — нулевая цена выключенного Locate.

### Сырой адрес и наложение каналов в `dmxoutPOP`
- **Context**: требование 7 — значение на каналы юниверса выхода в обход патча, остальные каналы юниверса — 0,
  прочие юниверсы — как без Locate.
- **Sources Consulted**: опыт на стенде `/project1/stand/spike_raw` (два `dmxfixturePOP` в один `dmxoutPOP`, Art-Net
  на 127.0.0.5, перехват `tools/dmx_listen.py`).
- **Findings**:
  - Источник A (10 RGB-ячеек с канала 1) и B (2 ячейки с канала 4) в одном юниверсе: каналы 4–9 всегда от B — и когда
    B ярче (255 против 127), и когда тусклее (51 против 255). Побеждает последний в списке `fixture` узла вывода.
  - Узел пишет предупреждение «Multiple fixtures using the same channels within a universe».
  - `dmxoutPOP` имеет `fixtureNactive` — источник можно держать в списке выключенным.
  - Адрес назначения берётся из примитивного атрибута `DMXFixtureNetAddress`; юниверс без строки в таблице
    маршрутизации всё равно уходит на этот адрес.
- **Implications**: сырой адрес = своя геометрия «512 каналов по одному на ячейку» на юниверсе цели, с адресом выхода,
  свой `dmxfixturePOP`, последним в списке `dmxoutPOP` группы этого выхода, `active` по команде. Перекрывает весь
  юниверс (7.2) без правок `hook` и таблиц движка. Предупреждение узла о наложении — ожидаемое, счётчики его не
  передают в `onOutputError`, пока сырой адрес включён.

### Запись патча и автоперезагрузка
- **Context**: требования 8.1, 8.2, 8.6 — статус сразу в файл, цель и режим сохраняются.
- **Sources Consulted**: `src/td/dsm_engine_ext.py` (`CheckFile`, `LoadPatch`, `loaded_mtime`), `docs/core-api.md`
  (`set_acceptance`, `fix_reversed`, `save` через временный файл), замер `perf` спеки `pixel-engine` (Reload 0,32 / 0,49 / 0,99 с).
- **Findings**:
  - Статус приёмки не влияет на геометрию и вывод; направление (`fix_reversed`) — влияет (порядок ячеек).
  - Автоперезагрузка сравнивает дату файла с `loaded_mtime`; запись без обновления `loaded_mtime` вызовет полную пересборку.
- **Implications**: расширение движка получает `SavePatch(patch, rebuild)` — единственный владелец записи файла патча:
  резервная копия при первой записи за сеанс, `api.save`, обновление `loaded_mtime`; `rebuild=False` — подмена патча
  в памяти и `info` без пересборки, `rebuild=True` — `LoadPatch`. Пригодится `mapping-editor` и `patch-view`.

### Событие «патч загружен» внутри компонента
- **Context**: 1.9 — после перезагрузки сохранить цель, если она есть в новом патче.
- **Findings**: колбэк `onPatchLoaded` — политика пользователя (DAT `Callbacks`), занимать его внутри компонента нельзя.
- **Implications**: в расширении движка — внутренний список слушателей `AddListener(fn)`; Locate подписывается при
  инициализации. Движок не знает про Locate.

### Клавиши только при фокусе панели
- **Context**: 11.3.
- **Findings**: `keyboardinDAT` имеет пару `panels` — события только при фокусе указанных панелей.
- **Implications**: `ui_test/keys` с `panels = ui_test`.

## Architecture Pattern Evaluation

| Option | Description | Strengths | Risks / Limitations | Notes |
|---|---|---|---|---|
| Шейдер в `hook` + таблица на фикстуру | `glslPOP` подменяет `Color` по `fx`/`cell`, данные цели — массив из CHOP | без пересборки, Python только по команде, обход при выключенном | цена шейдера на 50 тыс. ячеек | выбран |
| Новые колонки в `geo_cells` под Locate | цель как атрибут точки | просто в шейдере | смена цели = запись таблицы на 50 тыс. строк и перекук `dattoPOP` (десятки мс), нарушает 10.4 | отклонён |
| Сырой адрес через `dmxoutCHOP` | отдельный узел вывода CHOP на юниверс | независим от движка | два потока на один юниверс — контроллер мерцает между ними; нужно гасить юниверс в движке | отклонён |
| Сырой адрес — фикстура последней в `dmxoutPOP` | см. опыт | один поток, перекрывает весь юниверс | предупреждение узла о наложении | выбран |

## Design Decisions

### Decision: обобщить «цель» до набора фикстур
- **Context**: 1.1–1.3, 4.4, 5.x, 6.x — фикстура, несколько, группа, выход, порт, обход, паттерны.
- **Selected Approach**: любая цель разрешается чистой функцией в упорядоченный набор индексов фикстур; шейдер знает
  только флаг «в цели» на фикстуру. Тест-паттерн — режим, где цель = все выводимые фикстуры.
- **Rationale**: одна таблица и один шейдер на все виды цели; новые виды цели (зоны, выделение холста) — только разбор.

### Decision: чистая логика отдельно от TD
- **Selected Approach**: `src/td/dsm_locate.py` без TD-API (разбор цели, порядок обхода, раскладка номера, строки таблицы
  на фикстуру, лист приёмки, CSV, эталон цвета ячейки для стенда); `src/td/dsm_locate_ext.py` — расширение с TD-API.
- **Rationale**: pytest без TD (12.1), эталон для перехвата (12.2) из того же модуля.

### Decision: номер и адрес считаются в шейдере по числам на фикстуру
- **Selected Approach**: в таблицу на фикстуру кладутся число для показа (номер или юниверс и канал), число ячеек,
  смещение фикстуры в общем порядке; раскладка «сотни / десятки / единицы» — в шейдере по `cell`.
- **Rationale**: смена режима — только униформа, без записи таблицы.

### Decision: время мигания и бега — униформа от `absTime.seconds`, фаза для стенда — внутренняя пара
- **Selected Approach**: униформа `uTime` — выражение `absTime.seconds` (оптимизированный движок выражений, не Python-кук);
  внутренняя пара шейдера `uFreeze` (−1 — живое время) даёт стенду фиксированную фазу.
- **Rationale**: перехват байт в байт требует детерминированной фазы мигания и бега (12.2).

## Risks & Mitigations
- Цена шейдера на 50 тыс. ячеек выше 0,5 мс — замер в задаче шейдера; запас: шейдер в обходе при выключенном Locate,
  ветвления по режиму униформой (однородные для всех потоков).
- Предупреждение `dmxoutPOP` о наложении каналов при сыром адресе засоряет `info` — фильтр текста в счётчиках, пока
  сырой адрес активен.
- Запись файла патча под чужим редактором (файл открыт в другой программе) — `api.save` пишет через временный файл;
  ошибка записи → прежний файл, сообщение (8.5).
- Порядок реплик вывода после пересборки: сырая фикстура должна оставаться последней в списке — колбэк репликатора
  вывода дописывает её последней (проверка на стенде).
