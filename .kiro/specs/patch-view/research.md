# Research & Design Decisions — `patch-view`

## Summary
- **Feature**: `patch-view`
- **Discovery Scope**: Extension (лёгкое исследование): первая панель интерфейса в компоненте `dsm`; ядро даёт всё для
  карты и правок, движок — запись патча (`SavePatch`, `locate-test` 1.1) и перезагрузку с пересборкой.
- **Key Findings**:
  - Карту нельзя строить из панельных COMP на каждый сегмент: 100 юниверсов × до 10 сегментов — сотни панелей,
    каждое изменение патча — пересборка панелей, плюс известная цена перепроверки панельных выражений в TD.
    Карта рисуется как TOP: таблица прямоугольников → инстансинг → `renderTOP` (тот же приём, что превью
    движка `diag/preview_render`), попадание мышью считается по `panel.u/v` в Python по событию.
  - Списки (проблемы, выходы, порты, лист адресов) — только клон `listCOMP` из `op.TDTox` с внешним конфигом
    (мануал twozero `lister`): ручная сборка таблиц из панелей запрещена, у клона есть выбор, сортировка, прокрутка;
    переносимость — `parentshortcut` и ни одного `op()` в eval-колонках.
  - Параметры выхода и порта удобно править через `parameterCOMP`, привязанный к кастом-парам служебного COMP
    (`output_edit`): TD даёт поля, меню и проверку типов бесплатно, Python — только в `parameterexecuteDAT`.
  - Запись патча живёт в ветке `spec/locate-test`; по решению заказчика принятые части (1.1–3.3) идут в `main`
    отдельным PR до реализации `patch-view` (открыт PR fmusikhin/diod-sticks-mapper#5).

## Research Log

### Как рисовать карту юниверсов
- **Context**: 2.1–2.7, 9.1–9.3 — до 100 строк юниверсов с сегментами, перестройка ≤ 1 с, предпросмотр ≥ 20 Гц,
  Python только по событиям.
- **Sources Consulted**: мануал twozero `ui_building` (§ 4 авто-раскладка, § 7 репликаторы, § 15.8 зависание раскладки
  при чтении геометрии панелей, `optimization` S9 — перепроверка выражений панелей на каждую смену пар корня);
  `diag/preview_render` движка (ортографическая камера `tz=100`, `geometryCOMP` с инстансингом, `renderTOP`).
- **Findings**:
  - Панель-на-сегмент: сотни `containerCOMP`, каждая смена патча пересобирает их; выражения на панелях —
    перепроверка на каждую смену пар корня; чтение `.width` панелей в кадре смены `display` замораживает раскладку.
  - TOP из инстансов: одна таблица `rects` (x, y, w, h, r, g, b, a, kind) → `dattoCHOP` → `geometryCOMP`
    (`instancing`, `instanceop` CHOP, прямоугольник 1×1) → `renderTOP` ортокамерой в размер области карты;
    смена патча = одна запись таблицы (сотни строк), кадр — GPU; обводки конфликтов — второй слой инстансов.
  - Попадание: `panelexecuteDAT` на области карты даёт `u/v` и `lselect`; строка = `floor((1−v)·rows)`,
    канал = `floor(u·512)+1`; поиск сегмента — по таблице строк в Python по событию.
  - Перетаскивание: пока `lselect`, на каждое изменение `u/v` Python считает предпросмотр (`layout_fixture` ядра
    с пробным адресом → сегменты; пробный `validate` на копии патча → конфликты) и пишет таблицу `preview_rects`
    (десятки строк) — это события мыши, не кук кадра; 20 Гц достижимы (расчёт ядра — миллисекунды).
- **Implications**: модуль `dsm_patchview` строит строки таблиц и считает попадание/адрес чисто (pytest); панель
  показывает TOP в `containerCOMP.par.top`; крупный юниверс — та же схема с 512 клетками.

### Списки и редактирование параметров
- **Context**: 3.2 список проблем, 5.1–5.3 выходы и порты, 7.2 лист адресов.
- **Sources Consulted**: мануал twozero `lister` (клон `op.TDTox.op('lister')` + копия `listerConfig`, `colDefine`
  транспонирована, `Inputtabledat` — имя соседа, `Autodefinecols=False` после `colDefine`, цвет строк через
  `SetCellOverlay`, переносимость — без `op()` в eval-колонках, приёмка — `.tox` в другом месте без ошибок).
- **Findings**: источники списков — таблицы DAT от расширения (`issue_table`, `address_table`, строки выходов и
  портов); производные колонки считаются в источнике, не в eval; выбор строки → колбэк `onSelectRow` в конфиге →
  метод расширения через `parent.dmx`. Правка параметров выхода/порта — `parameterCOMP` на кастом-парах
  `output_edit`/`port_edit` + `parameterexecuteDAT` → `update_output`/`update_port`.
- **Implications**: четыре листера с общим паттерном; расширение держит «текущий выход» и «текущий порт»
  и перезаполняет служебные пары без повторного входа (флаг, как в Locate).

### Запись патча и перезагрузка
- **Context**: 6.1–6.4 — правка → файл → пересборка → вывод ≤ 2 с; карта движка сверяется с ядром.
- **Sources Consulted**: `DsmEngineExt.SavePatch(edit, rebuild)` (`locate-test` 1.1: документ перечитывается из файла,
  правка применяется к нему и к рабочему патчу, резервная копия, `.tmp` убирается, ошибка не гасит вывод),
  `LoadPatch` (пересборка 0,3–1 с на 14–50 тыс. ячеек), `RefreshMaps` и `tables/map_sets` → `diag/dmxmap_all`.
- **Findings**: любая правка адресов меняет геометрию → `rebuild=True`; `auto_assign_all` при загрузке пересчитает
  авто-адреса — сообщение «сдвинулось N» считается сравнением адресов до и после; сверка 6.4 — `RefreshMaps(True)`
  и чтение `dmxmap_all` против `segment_table` через ~40 кадров (как в стенде `examples`).
- **Implications**: отмена — документ файла до правки (`api.load`) хранится в памяти, «отменить» = `SavePatch(lambda p: prev, True)`.

### Ветка и слияние
- **Context**: `patch-view` от `main`; `SavePatch` и хуки — в `spec/locate-test`.
- **Findings**: `git switch` на `main`-ветку убрал с диска файлы Locate, на которые смотрят DAT с `syncfile` в
  dev-проекте (предупреждения «File not found for sync», движок без `SavePatch` после reinit). Рабочее дерево
  выровнено: файлы `locate-test` возвращены как неотслеживаемые/изменённые, в коммиты `patch-view` не входят.
- **Implications**: реализация `patch-view` начинается после слияния PR #5 и подтягивания `main` в ветку;
  до этого — только документы спеки.

## Architecture Pattern Evaluation

| Option | Description | Strengths | Risks / Limitations | Notes |
|---|---|---|---|---|
| Карта из панельных COMP (репликатор на сегмент) | строка-контейнер на юниверс, контейнер на сегмент | hover/клик бесплатно | сотни панелей, пересборка на каждую правку, цена перепроверки выражений, зависание раскладки | отклонён |
| Карта как TOP из инстансов + попадание в Python по событию | таблица прямоугольников → инстансинг → renderTOP | одна запись таблицы, GPU в кадре, любой масштаб | попадание и подсказки считаются вручную | выбран |
| Карта как `listCOMP` (строка = юниверс, 512 колонок) | листер с ячейками-каналами | выбор/прокрутка готовые | 512 колонок × 100 строк — не для листера, нет полосок произвольной ширины | отклонён |
| Поля выхода руками (`textCOMP` editable) | свои поля на каждый параметр | полный контроль вида | ~15 полей × проверка типов руками | отклонён в пользу `parameterCOMP` |

## Design Decisions

### Decision: таблицы прямоугольников — граница Python/GPU и единственный источник карты
- **Selected Approach**: чистый модуль считает строки `map_rects` (сегменты, подложки юниверсов, недоступные 511–512,
  обводки конфликтов) и `zoom_rects` (512 клеток выбранного юниверса); расширение пишет их одной операцией.
- **Rationale**: тот же приём, что таблицы движка — pytest без TD, перестройка = одна запись, кадр без Python.

### Decision: попадание и адрес по точке — чистые функции
- **Selected Approach**: `hit(u, v, layout) -> (row, channel, segment|None)`, `drop_address(layout, row, channel, snap)`
  — по тем же строкам, что нарисованы; предпросмотр — `preview(patch, fixture_id, output_id, universe, channel)`
  через `layout_fixture`/`validate` ядра на пробном патче.
- **Rationale**: перетаскивание и клик тестируются pytest; панель лишь передаёт `u/v`.

### Decision: правки — только через ядро и `SavePatch(rebuild=True)`
- **Selected Approach**: каждая команда = функция правки ядра → `SavePatch(edit, True)`; до правки — документ файла
  в памяти для отмены; после перезагрузки — слушатель движка перестраивает карту и сверяет с `dmxmap_all`.
- **Rationale**: патч — источник правды (принцип 2), файл и вывод всегда совпадают; одна точка записи в движке.

### Decision: списки — клоны `listCOMP`, поля — `parameterCOMP`
- **Rationale**: мануал twozero запрещает ручные таблицы из панелей; `parameterCOMP` даёт проверку типов и меню.

## Risks & Mitigations
- Цена перестройки карты на 100 юниверсов — одна таблица на сотни–тысячи строк; замер в стенде, порог 1 с.
- `renderTOP` под Non-Commercial ≤ 1280×1280 — область карты ≤ 1280×720, укладывается.
- Листер: тихие провалы (0 строк без ошибки) — следовать чеклисту мануала, приёмка — `.tox` в другом месте.
- Правка адреса auto-фикстур пересчитывает соседей — сообщение «сдвинулось N» и отмена одной ступенью.
- Зависание раскладки панелей (TD, § 15.8) — не читать геометрию панелей из скриптов, размеры — из пар.
