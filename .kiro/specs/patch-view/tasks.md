# Implementation Plan — `patch-view`

Порядок задач = зависимость: задача N опирается на всё до неё, если не сказано иное. Маркеров `(P)` нет: чистая логика
живёт в одном модуле, а все правки компонента идут в один живой `.toe` через один инстанс TD. Каждая подзадача
заканчивается «чем проверено»: pytest, `td_get_errors`, `td_audit_panel`, перехват байт в байт или замер («готово — только
с фактом проверки»). Правки `.toe` — только через twozero; `td_get_hints('bootstrap')` в начале сессии; перед панелью —
мануалы `ui_building` и `panel_layout`, перед первым листером — `lister` и `td_get_docs('lister')`; сохранение — `safe_save`;
стенды `/project1/stage0`, `/project1/stand/spike*` не трогаются. Задача 5 — документация: правила генерации её исключают,
но требование 10.4 обязывает; оставлена проверяемая часть (режим `docs`, контрольная точка).

Внешний гейт: PR fmusikhin/diod-sticks-mapper#5 (`locate-test` 1.1–3.3) сливает заказчик; задача 1.1 начинается после слияния.

Отложено с обоснованием: перетаскивание строки из листера на TOP-карту (3.3) — только если мануал `lister` даёт колбэк
drop; иначе «выбор строки + клик по карте» (3.6). Подряд для нескольких фикстур (4.5) в UI — множественный выбор в листе
адресов + кнопка (3.7); если множественного выбора в листере нет — только методом, записать в Notes.
