# CONTRIBUTING — правила разработки DSM

Язык документации, коммитов и общения — русский.

## 1. Порядок работы

- Сначала план → подтверждение → действия.
- SDD (cc-sdd): одна спека = одна фича; требования, решение и шаги утверждаются до реализации.
  Спеки — `.kiro/specs/<имя>/`.
- Агент и разработчик работают бок о бок: разработчик правит патч в TouchDesigner напрямую,
  агент — только через twozero MCP.

## 2. Что коммитим, что нет

- ✅ Исходники-текст: ядро `src/core`, расширения `src/td`, шейдеры `src/glsl`, тесты, примеры патчей,
  документация. Текст — источник правды.
- ✅ Dev-проект `td/*.toe` — только канонический файл (без номера автосейва) и только на контрольных точках,
  не каждый промежуточный сейв.
- ⛔ Нумерованные автосейвы `*.N.toe`, `Backup/`, кэши, видео и тяжёлое медиа — всё в `.gitignore`.
- ⛔ Собранный `dsm.tox` в историю не кладём — он уходит ассетом в GitHub Releases.
- ⛔ Реальные IP, планы площадок и данные заказчиков — никогда (репозиторий публичный).
  Тестовые образцы — синтетические.
- `.toe` и `.tox` — обычные бинарники git, **без LFS**.

## 3. Git

- `main` — всегда рабочее состояние.
- Спека → ветка `spec/<имя>` → PR → слияние в `main` после ревью владельца.
- Мелкие правки документации и настроек — коммит сразу в `main`.
- `git pull --rebase` перед пушем. Коммитим часто локально, пушим пачкой в конце шага.
- Один коммит / PR — одна осмысленная единица; сообщение по-русски, по сути.
- К GitHub API — только через `gh` (авторизованный лимит); не обращаться к `api.github.com` без токена.

## 4. Контракт компонента

DSM — компонент, который бросают в чужой патч, и он работает.

- **Не знает о проекте-хозяине.** Никаких абсолютных путей и допущений про соседей; ссылки — относительные
  или через `parentshortcut`. Глобальный OP-шорткат не заводим: при нескольких копиях маппера он тихо конфликтует.
- **Публичный контракт — кастом-пары и коннекторы.** Что можно дёрнуть снаружи — видно в параметрах.
- **Обязательные пары на странице `Info`**, все `readOnly`:

  | Пара | Формат | Смысл |
  |---|---|---|
  | `Id` | `dsm/mapper` | идентификатор компонента |
  | `Version` | `MAJOR.MINOR`, напр. `1.00` | версия контракта; `float(par.Version)` обязан работать |

- **Бамп версии:** `MINOR` — обратно-совместимое (новый колбэк, необязательная пара, фикс);
  `MAJOR` — ломающее (пара переименована или удалена, сменилась сигнатура колбэка, тип выхода,
  несовместимый формат патча). Бамп → `CHANGELOG.md`.
- **Механика — пара, политика — колбэк.** Поведение под задачу настраивается DAT-ом колбэков
  (`onPatchLoaded`, `onLocate`, `onOutputError`, `onBeat` …). Новая пара — только если без неё никак:
  новый колбэк почти бесплатен, новая пара — навсегда.
- **Адаптация — три уровня, начинаем с первого:** (1) конфигурация — значения пар и свои колбэки;
  (2) враппер вокруг немодифицированного `dsm.tox`; (3) форк — последнее средство.
- **`.tox` — пустая заготовка:** без загруженного патча, контента и накопленного состояния.
  Имя файла без версии — `dsm.tox`; версия живёт в `par.Version`, в `CHANGELOG.md` и в теге релиза.
- Внутри компонента — DAT `agents_md` с описанием контракта.

## 5. Дым-тест перед релизом `.tox`

Битый `.tox` выглядит ровно как рабочий, поэтому перед каждым релизом:

1. Загрузить `dsm.tox` в пустой COMP нового проекта.
2. Проверить имя корневого опа, `Id` и `Version`.
3. Проверить отсутствие `scriptErrors()` и `errors()`.
4. Загрузить пример патча из `examples/`, убедиться, что вывод идёт на 127.0.0.1 и совпадает с ожидаемой таблицей.

## 6. Работа агента в TouchDesigner

- `.toe` правится только через twozero MCP; сторонние бинарные правки — нельзя.
- Перед первым действием в TD за сессию — `td_get_hints('bootstrap')`.
- Запущено несколько TD — всегда передавать `target_instance`, инстанс опознавать по имени проекта.
- После правки — `td_get_errors` на затронутом узле.
- Разработчик мог править патч параллельно. Если в `.toe` есть изменения, которых агент не делал, —
  это правки разработчика, их сохраняем. Сначала проверка на подозрительное: откат версии,
  два открытых похожих проекта, пустой или битый сейв. Подозрительно — спросить.

## 7. Документация

- README и документы отражают **текущее** состояние; история — в `CHANGELOG.md`.
- Разошлись с реальностью — правим док сразу, долги по докам не копим.
- «Готово» — только с фактом проверки: pytest, сверка DMX Map DAT, перехват Art-Net/sACN, замер кадра.
