# Архитектура DSM

Черновик архитектуры по итогам планирования (октябрь 2026). Источник для steering и спек cc-sdd:
когда спека утверждена, правдой считается она, а этот документ обновляется следом.

## 1. Задача

Универсальный продвинутый DMX-маппер для TouchDesigner в виде одного `.tox`, который вставляется в любой патч:

- на вход — TOP с видео;
- внутри — фикстуры (создание, редактирование, профили), направление входного сигнала, адресация;
- на выход — Art-Net / sACN для LED-стиков, лент, матриц и пиксельных приборов;
- максимальная синхронизация с видеоконтентом.

Главный урок прошлого прототипа: он был собран под конкретные контроллеры (жёсткие размеры сетки,
отдельные цепочки нод на каждый контроллер), и каждая смена железа требовала перестройки движка.
Здесь движок о железе не знает ничего.

## 2. Принципы

1. **Движок не знает про железо.** Контроллер — это данные: IP, протокол, юниверсы.
2. **Патч — документ и источник правды** (JSON). Геометрия, адреса, маршрутизация, интерфейс
   и отчёты генерируются из него.
3. **Каждый кадр — только GPU** (POP и GLSL). Python — только при правке патча.
4. **Один вход TOP**, несколько копий в одном проекте, без абсолютных путей.
5. **Интерфейс помещается в 1280×720.**
6. **Безопасные умолчания:** вывод на 127.0.0.1, пока у выхода не задан IP; тест на 30 %.

## 3. Модель данных патча

```
patch.json
├─ canvas        размер, единицы (px или метры), подложка (план площадки)
├─ fixture_types профиль фикстуры:
│                 тип: лента | стик | матрица W×H | бар | свой
│                 блоки каналов: [общие на прибор] [на пиксель: порядок строкой "GRBW", 8/16 бит,
│                                 свои каналы ячейки] [хвост]
│                 раскладка матрицы: 16 вариантов (угол старта, строки/столбцы, змейка)
│                 физика: длина, шаг пикселя, px/м
│                 цвет: гамма, баланс белого, режим выделения W; ватт на пиксель
├─ fixtures      экземпляр:
│                 профиль, группы
│                 вход: форма на картинке (линия | полилиния | кривая | дуга | прямоугольник)
│                       + выборка (точка | область | вытянутая область, ширина)
│                 выход: физическая форма (2D, позже 3D)
│                 направление сигнала (начало/конец), сдвиг, отключённые пиксели, каждый N-й
│                 адрес: выход, юниверс и канал (авто или вручную)
│                 яркость, цвет, mute; статус приёмки (Locate)
├─ outputs       аналог Lumiverse:
│                 протокол Art-Net / sACN; IP, broadcast или multicast; net.subnet.universe старта
│                 правила: пиксель не делится, Auto Span, пропуск 511–512, выравнивание 170/510
│                 порты (необязательно): порядок фикстур в цепочке, «порт с нового юниверса»,
│                 лимит пикселей на порт (для проверки)
│                 частота, ArtSync, priority (sACN), задержка в мс
└─ groups
```

## 4. Конвейер кадра

```
вход TOP
  → подготовка (кроп, ограничение разрешения, уровни)
  → режим источника: КОНТЕНТ | ПАЛИТРА (сегменты или генератор 1–12) → кроссфейд
  → текстура

патч → (Python, только при правке) → POP-геометрия:
        1 примитив = 1 фикстура, 1 точка = 1 ячейка в порядке данных
        атрибуты точки: UV на картинке (по длине дуги), позиция, индекс ячейки
        атрибуты примитива: DMXFixtureUniverse / DMXFixtureChannel / DMXFixtureNetAddress
  → выборка цвета (Lookup Texture POP или GLSL с несколькими отсчётами)
  → пиксельная обработка (GLSL POP): Locate/тест, генераторы «по фикстурам», яркость,
    баланс белого, гамма, RGB→RGBW, лимит мощности (сумма через Analyze POP), раскладка каналов
  → DMX Fixture POP — по одному на профиль (страница профиля генерируется из типа)
  → один DMX Out POP на протокол; таблица маршрутизации (IP и priority на юниверс);
    Multipliers = мастер
```

Сколько бы ни было контроллеров и фикстур — один DMX Fixture POP на профиль и один DMX Out POP
на протокол. По документации TD 2025: адрес задаётся атрибутами примитива, для каждого IP
каналы считаются независимо, DMX Out POP сливает любое число DMX Fixture POP.

## 5. Адресация

Ядро на чистом Python, без TD, с тестами pytest.

- Режимы: авто (как Lumiverse, с правилами порта) и вручную.
- Проверки: пересечения каналов, выход за 512, пиксель на границе юниверса, лимиты порта,
  дубли IP, перенос в Net/Subnet (Art-Net 4, 15-битный адрес порта).
- На выходе: таблица адресов, таблица маршрутизации, лист патча для монтажников (HTML/MD), CSV.
- Дубль группы получает адреса блоком, по порядку.

## 6. Синхронизация с видео

- Маппер берёт тот же TOP, что уходит на экраны, в том же кадре — без NDI и второй программы.
- Частота вывода = fps проекта или делитель; ArtSync; выше 44 Гц для пиксельных контроллеров.
- Задержка на каждый выход в мс, чтобы LED совпадал с экраном или проектором.
- Если кадр выпал — повторяется последний.

## 7. Интерфейс

Вкладки **INPUT MAP | OUTPUT MAP | DMX | FIXTURES | TEST**, переключатель **КОНТЕНТ / ПАЛИТРА**.

- **Холст** (GLSL): картинка под фикстурами, стрелка направления, точки пикселей, номера;
  выделение рамкой, группы, поворот и масштаб выделения; привязки к сетке, концам и углу;
  стрелки и Shift+стрелки; Alt-дубль, Ctrl+D (повтор смещения), генератор массива с адресами подряд;
  undo/redo.
- **Инспектор**: правка нескольких фикстур сразу.
- **DMX**: сетка юниверсов по выходам, перетаскивание = новый адрес, конфликты красным.
- **FIXTURES**: редактор профиля блоками, пресеты (WS2811, WS2812B, SK6812 RGBW, TM1934, стик 1 м,
  матрица 16×16, бар с общими каналами).
- **TEST**: Locate, паттерны, монитор.
- **Строка состояния**: пиксели, юниверсы, fps, пакетов в секунду, предупреждения.

## 8. Locate — найти фикстуру на площадке

Вызов: клик по фикстуре на холсте, в списке или на карте DMX; номер или имя; горячая клавиша.

| Режим | Что делает |
|---|---|
| Мигание | фикстура мигает, остальные гаснут (соло) или приглушены |
| Направление | первый пиксель красный, последний синий, бегущая точка от начала к концу |
| Номер на пикселях | группы пикселей: сотни красным, десятки зелёным, единицы синим |
| Обход | «следующая / предыдущая» по порядку патча, автошаг |
| Группа, выход, порт | зажечь целиком группу, IP или цепочку порта |
| Сырой адрес | сигнал на юниверс и каналы в обход патча |

Лист приёмки: статусы «ок / перевёрнута / не горит / не на месте / не тот адрес» сохраняются
в патч; «перевёрнута» исправляется одной кнопкой. Позже — управление Locate с телефона
(веб-страница на `webserverDAT`).

Реализация: таблица целей и режима → GLSL в пиксельной обработке; мигание и бег считаются
в шейдере по времени. Критерий: от клика до мигания не больше 2 кадров.

## 9. Палитра и генераторы

Отдельный модуль внутри tox, работает и сам по себе.

1. Контент уменьшается до ~64×36.
2. Основные цвета — k-means на GPU в OKLab, по умолчанию **5 цветов** (2–8); старт с прошлого
   кадра, чтобы цвета не прыгали; сглаживание по времени.
3. Опции: не брать чёрный и тёмный, заморозить палитру.
4. Выход: палитра (TOP и CHOP: r, g, b, доля площади) и поле для маппера.

Режимы поля: **СЕГМЕНТЫ** (каждый пиксель → ближайший цвет палитры) или **генератор 1–12**:

| № | Генератор | Где |
|---|---|---|
| 1 | линии бегут вверх / вниз | поле |
| 2 | линии бегут влево / вправо | поле |
| 3 | диагональные линии, угол настраивается | поле |
| 4 | встречные линии: от краёв к центру и обратно | поле |
| 5 | круги расходятся от центра | поле |
| 6 | круги сходятся к центру, пульс | поле |
| 7 | вращающийся луч и спираль | поле |
| 8 | плавные цветовые волны (плазма) | поле |
| 9 | хвост бежит вдоль каждого стика со сдвигом по номеру | по фикстурам |
| 10 | стики заполняются от начала к концу | по фикстурам |
| 11 | стики мягко загораются и гаснут вразнобой | по фикстурам |
| 12 | цвет перетекает по риге: по порядку патча или от точки | по фикстурам |

Общие ручки: скорость (накопитель фазы — без рывков при смене), ширина, плотность, угол,
мягкость краёв (по умолчанию плавно, синусоидально), точка центра, сдвиг палитры.
Все ручки — параметры tox, их можно привязать снаружи.

## 10. Темп (beat-sync)

Генераторам нужен не только BPM, но и фаза — чтобы попадать в долю.

Источники в первой версии — **без пульта**:

- **внутренний BPM** (число);
- **TAP** — кнопка в интерфейсе;
- **Ableton Link** — темп из диджейского софта;
- **свободная скорость** без привязки к темпу.

При синхронизации скорость задаётся долями: цикл за 1/4, 1/2, 1, 2, 4 доли; опции — акцент
на первую долю такта, смена цвета палитры на долю.

**Позже — пульт grandMA2** (отложено): бит-клок по DMX. На пульте — 16-битный не-диммерный
канал с эффектом-«пилой» на такт, привязанным к спидмастеру (не-DIM — чтобы Grand Master
и Blackout не гасили). В TD фаза такта из пилы, BPM из периода, внутренний генератор фазы
плавно подстраивается; при пропаже сигнала держится последний темп. Гипотеза, проверяется на пульте
одной строкой перед спекой.

## 11. Упаковка

- Вход: TOP. Параметры tox: `Patchfile`, `Active`, `Master`, `Rate`, `Artsync`, `Latency`,
  `Localaddress`, режим источника, генератор, источник темпа, `Openeditor`, тест-режимы.
- Выходы: превью TOP, пиксели как TOP и CHOP, палитра, info.
- Исходники: ядро — Python-модуль вне TD; расширения и шейдеры — внешние файлы, синхронизированные с DAT.
- Релизы `dsm.tox` — в GitHub Releases.

## 12. Проверка

- Ядро — `pytest` вне TD.
- В TD — сверка `DMX Map DAT` с ожидаемой таблицей адресов; перехват Art-Net/sACN на 127.0.0.1
  байт в байт; замер стоимости кадра.
- Стенд с железом — в конце этапа.
- Критерии MVP: 100 стиков × 144 px на 8 IP патчатся за 10 минут или быстрее; перехват совпадает
  с таблицей; маппер не дороже 1 мс на кадр при 20 тыс. пикселей, 60 fps.

## 13. Этап 0 — проверки движка в TD

1. Один DMX Out POP + несколько DMX Fixture POP с адресом на каждую фикстуру и разными IP,
   Art-Net и sACN; сверка перехватом.
2. Фикстуры разной длины на 50 тыс. пикселей: способ генерации точек и его стоимость.
3. Шлёт ли вывод каждый кадр без принудительного кука из Python; поведение с недоступным IP
   (в прошлом прототипе он опускал fps до ~30).

## 14. Грабли TouchDesigner, известные заранее

- `active` — зарезервированное слово в шейдерах POP; массивы-униформы объявляются сами.
- `ext0object` — просто имя оператора, без путей.
- Колесо мыши на панели — брать `val - prev`, а не накопленное значение.
- Кнопки из container + text — текст с `clickthrough`.
- Не переименовывать `annotateCOMP` после создания.
- Анимацию со скоростью — через накопитель фазы, а не `absTime * speed` (рывок при смене скорости).
- На части контроллеров мерцает юниверс 0 и рвётся последний юниверс в пачке — это опции выхода
  (стартовый юниверс, «защитный» юниверс, ArtSync), а не заплатки в движке.

## 15. Открытые вопросы

- Сборка TD (предложено 2025.33070) и лицензия (ограничение TOP 1280×1280 при Non-Commercial).
- Имя tox (`dsm.tox`).

- Пульт и путь бит-клока — когда вернёмся к варианту с пультом.
