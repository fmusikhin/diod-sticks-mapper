# Diod Sticks Mapper (DSM)

Универсальный Art-Net / sACN пиксель-маппер для TouchDesigner в виде одного `.tox`.

## Спеки разработки

Разработка идёт по SDD (cc-sdd): у каждой фичи своя спека, фазы
**требования → решение → шаги → реализация**, каждая фаза утверждается до перехода к следующей.
Папка спеки — `.kiro/specs/<имя>/` (`requirements.md`, `design.md`, `tasks.md`), появляется при старте спеки.

| № | Спека | Что внутри | Этап |
|---|---|---|---|
| — | этап 0 (без спеки) | репозиторий, cc-sdd, steering, проверки движка в TD | 0 |
| 1 | `patch-core` | модель патча, JSON-схема, адресация, проверки, импорт/экспорт CSV/JSON, pytest — без TD | 1 |
| 2 | `pixel-engine` | каркас tox, POP-геометрия из патча, выборка цвета, DMX-вывод, синхронизация с видео | 1 |
| 3 | `patch-view` | карта DMX по юниверсам, выходы и правила портов, переадресация перетаскиванием, конфликты | 1 |
| 4 | `mapping-editor` | холст INPUT / OUTPUT, инструменты, выделение, привязки, массивы, undo | 1–2 |
| 5 | `locate-test` | Locate: мигание, соло, направление, номер на пикселях, обход, сырой адрес, лист приёмки | 1 |
| 6 | `fixture-editor` | редактор профилей блоками, матрицы, бары с общими каналами, библиотека | 2 |
| 7 | `color-power` | 16 бит, RGBW, баланс белого, гамма, лимит мощности | 3 |
| 8 | `space-3d` | выходная карта в 3D, визуализатор | 3 |
| 9 | `palette-generators` | кнопка «Палитра»: из контента выделяются основные цвета (по умолчанию 5), в маппер идёт поле из них — сегментированная картинка или один из 12 генераторов; делается параллельно с MVP | 1 |
| 10 | `beat-sync` | темп и фаза для генераторов: внутренний BPM, тап, Ableton Link; BPM с пульта grandMA2 — позже | 1 |

## О проекте

Вставляется в любой патч: на вход — TOP с видео, на выход — DMX для LED-стиков, лент,
матриц и пиксельных приборов, синхронно с видеоконтентом.

Главный урок прошлого прототипа: он был собран под конкретные контроллеры (жёсткие размеры сетки,
отдельные цепочки нод на каждый контроллер), и каждая смена железа требовала перестройки движка.
Здесь движок о железе не знает ничего.

## Идея: Resolume как образец

Модель взята у Resolume Arena Advanced Output (актуальная ветка 7.x): библиотека фикстур,
размещение фикстур поверх картинки (Input Map), карта каналов (DMX), выходы-«лумиверсы».

**Что переносим из Resolume**

| В Resolume | В DSM |
|---|---|
| Lumiverse: группа юниверсов с одной целью, Auto Span, пиксель не делится между юниверсами | «выход» = цель (IP или multicast) + стартовый юниверс; Auto Span и целый пиксель по умолчанию |
| Fixture Editor: сетка W×H, 16 вариантов раскладки, служебные каналы, гамма; правка профиля обновляет все копии | то же, плюс то, чего там нет (ниже) |
| размещение поверх живой картинки: привязки, мультивыбор, Alt-дубль, Ctrl+D, арифметика в полях | те же жесты; Ctrl+D ещё и раздаёт адреса подряд |
| вкладка DMX: перетаскивание меняет адрес, конфликты красным | карта юниверсов с теми же жестами и фильтром по выходам |
| пресет выхода отдельно от контента | патч — отдельный JSON, профили фикстур встроены в него |
| общие частота, задержка, ArtSync | есть, плюс задержка на каждый выход |

**Что в Resolume не так и как это закрыто**

| Resolume | DSM |
|---|---|
| только прямоугольные сетки | линия, полилиния, кривая, дуга, матрица, своя таблица точек |
| цвет берётся одной точкой в центре клетки — мерцание | точка, область, вытянутая область (вдоль/поперёк ленты) |
| нельзя отключить пиксель, нет шага и «каждый N-й» | отключение пикселя, шаг в мм, каждый N-й, пропуск мёртвых пикселей |
| служебные каналы только до/после пикселей | профиль блоками: общие каналы → пиксельный блок со своими каналами ячейки → хвост |
| порядок цвета из меню, RGBW без настроек, только 8 бит | порядок строкой (`GRB`, `BWGR`), RGBW/RGBWA с режимами белого, 8 и 16 бит |
| только Art-Net, без Net, ≤256 юниверсов на IP, одна сетевая карта | Art-Net 4, sACN unicast/multicast с priority, IP на юниверс, выбор сетевой карты |
| не знает портов контроллера | универсальные правила порта: «с нового юниверса», выравнивание 170/510, пропуск 511–512, лимит пикселей |
| дубль группы получает адреса вразнобой | адреса блоком, по порядку |
| нет импорта, массовые правки через XML | CSV/JSON, генератор массивов, Python-API |
| нет подсветки фикстуры, только общая тест-карта | **Locate**: мигание, соло, направление, номер на пикселях, обход, сырой адрес, лист приёмки |
| нет лимита мощности | общий бюджет и бюджет на выход |
| вывод около 40 Гц, не быстрее рендера | частота = fps проекта, ArtSync |
| нет 3D | выходная карта в 3D и визуализатор (позже) |

**Что стоит взять у других**

- MadMapper 6: фикстуры Line / Circle / Bézier / Matrix / Custom, выборка Point / Box / Anamorphic,
  отключение отдельного пикселя, пропуск 511–512, 8/16 бит, пакетное создание из CSV, раскладка по камере.
- MADRIX 5: генератор матриц, автоадресация, импорт CSV.
- ENTTEC ELM: Art-Net, sACN, KiNet, ArtSync, смещение адресов для слияния с пультом.
- TouchDesigner 2025: DMX Fixture POP (профиль блоками на точку или примитив, адрес атрибутами)
  и DMX Out POP (Art-Net / sACN / KiNET, маршрутизация по юниверсам, ArtSync, Multipliers) — основа движка.

## Принципы

1. **Движок не знает про железо.** Контроллер — это данные: IP, протокол, юниверсы.
   Никаких веток нод под конкретный контроллер.
2. **Патч — документ и источник правды** (JSON). Геометрия, адреса, маршрутизация,
   интерфейс и отчёты генерируются из него.
3. **Каждый кадр — только GPU** (POP и GLSL). Python — только при правке патча.
4. **Один вход TOP**, несколько копий в одном проекте, без абсолютных путей.
5. **Интерфейс помещается в экран 1280×720.**
6. **Безопасные умолчания:** вывод на 127.0.0.1, пока у выхода не задан IP; тест на 30 %.

## Модель данных патча

```
patch.json
├─ canvas        размер, единицы (px или метры), подложка (план площадки)
├─ fixture_types профиль фикстуры:
│                 тип: лента | стик | матрица W×H | бар | свой
│                 блоки каналов: [общие на прибор] [на пиксель: порядок строкой "GRBW", 8/16 бит,
│                                 свои каналы ячейки] [хвост]
│                 раскладка матрицы: 16 вариантов (угол старта, строки/столбцы, змейка)
│                 физика: длина, шаг пикселя, px/м
│                 цвет: гамма, баланс белого, режим выделения W; ватт на пиксель
├─ fixtures      экземпляр:
│                 профиль, группы
│                 вход: форма на картинке (линия | полилиния | кривая | дуга | прямоугольник)
│                       + выборка (точка | область | вытянутая область, ширина)
│                 выход: физическая форма (2D, позже 3D)
│                 направление сигнала (начало/конец), сдвиг, отключённые пиксели, каждый N-й
│                 адрес: выход, юниверс и канал (авто или вручную)
│                 яркость, цвет, mute; статус приёмки (Locate)
├─ outputs       аналог Lumiverse:
│                 протокол Art-Net / sACN; IP, broadcast или multicast; net.subnet.universe старта
│                 правила: пиксель не делится, Auto Span, пропуск 511–512, выравнивание 170/510
│                 порты (необязательно): порядок фикстур в цепочке, «порт с нового юниверса»,
│                 лимит пикселей на порт (для проверки)
│                 частота, ArtSync, priority (sACN), задержка в мс
└─ groups
```

## Конвейер кадра

```
вход TOP
  → подготовка (кроп, ограничение разрешения, уровни)
  → режим источника: КОНТЕНТ | ПАЛИТРА (сегменты или генератор 1–12) → кроссфейд
  → текстура

патч → (Python, только при правке) → POP-геометрия:
        1 примитив = 1 фикстура, 1 точка = 1 ячейка в порядке данных
        атрибуты точки: UV на картинке (по длине дуги), позиция, индекс ячейки
        атрибуты примитива: DMXFixtureUniverse / DMXFixtureChannel / DMXFixtureNetAddress
  → выборка цвета (Lookup Texture POP или GLSL с несколькими отсчётами)
  → пиксельная обработка (GLSL POP): Locate/тест, генераторы «по фикстурам», яркость,
    баланс белого, гамма, RGB→RGBW, лимит мощности, раскладка каналов
  → DMX Fixture POP — по одному на профиль
  → один DMX Out POP на протокол; таблица маршрутизации (IP и priority на юниверс); мастер
```

Сколько бы ни было контроллеров и фикстур — один DMX Fixture POP на профиль и один DMX Out POP
на протокол: адрес задаётся атрибутами примитива, для каждого IP каналы считаются независимо.

## Адресация

Ядро на чистом Python, без TD, с тестами pytest.

- Режимы: авто (как Lumiverse, с правилами порта) и вручную.
- Проверки: пересечения каналов, выход за 512, пиксель на границе юниверса, лимиты порта,
  дубли IP, перенос в Net/Subnet (Art-Net 4).
- На выходе: таблица адресов, таблица маршрутизации, лист патча для монтажников, CSV.

## Синхронизация с видео

- Маппер берёт тот же TOP, что уходит на экраны, в том же кадре — без NDI и второй программы.
- Частота вывода = fps проекта или делитель; ArtSync; выше 44 Гц для пиксельных контроллеров.
- Задержка на каждый выход в мс, чтобы LED совпадал с экраном или проектором.
- Если кадр выпал — повторяется последний.

## Интерфейс

Вкладки **INPUT MAP | OUTPUT MAP | DMX | FIXTURES | TEST**, переключатель **КОНТЕНТ / ПАЛИТРА**.

- **Холст**: картинка под фикстурами, стрелка направления, точки пикселей, номера; выделение рамкой,
  группы, поворот и масштаб выделения; привязки к сетке, концам и углу; стрелки и Shift+стрелки;
  Alt-дубль, Ctrl+D, генератор массива с адресами подряд; undo/redo.
- **Инспектор**: правка нескольких фикстур сразу.
- **DMX**: сетка юниверсов по выходам, перетаскивание = новый адрес, конфликты красным.
- **FIXTURES**: редактор профиля блоками и пресеты — WS2811, WS2812B, SK6812 RGBW, TM1934,
  стик 1 м, матрица 16×16, бар с общими каналами.
- **TEST**: Locate, паттерны, монитор.
- **Строка состояния**: пиксели, юниверсы, fps, пакетов в секунду, предупреждения.

## Locate — найти фикстуру на площадке

Вызов: клик по фикстуре на холсте, в списке или на карте DMX; номер или имя; горячая клавиша.

| Режим | Что делает |
|---|---|
| Мигание | фикстура мигает, остальные гаснут (соло) или приглушены |
| Направление | первый пиксель красный, последний синий, бегущая точка от начала к концу |
| Номер на пикселях | группы пикселей: сотни красным, десятки зелёным, единицы синим |
| Обход | «следующая / предыдущая» по порядку патча, автошаг |
| Группа, выход, порт | зажечь целиком группу, IP или цепочку порта |
| Сырой адрес | сигнал на юниверс и каналы в обход патча |

Лист приёмки: статусы «ок / перевёрнута / не горит / не на месте / не тот адрес» сохраняются в патч;
«перевёрнута» исправляется одной кнопкой. Позже — управление Locate с телефона.
От клика до мигания — не больше 2 кадров.

## Палитра и генераторы

Кнопка **ПАЛИТРА**: из контента в реальном времени выделяются основные цвета, и в маппер идёт
не сам контент, а поле из этих цветов.

1. Контент уменьшается до ~64×36.
2. Основные цвета — кластеризация на GPU в цветовом пространстве OKLab, по умолчанию **5 цветов** (2–8);
   каждый кадр стартует с прошлого результата, чтобы цвета не прыгали; сглаживание по времени.
3. Опции: не брать чёрный и тёмный, заморозить палитру.
4. Выход: палитра (r, g, b и доля площади каждого цвета) и поле для маппера.

Режимы поля: **СЕГМЕНТЫ** (каждый пиксель заменяется ближайшим цветом палитры) или **генератор 1–12**:

| № | Генератор | Где |
|---|---|---|
| 1 | линии бегут вверх / вниз | поле |
| 2 | линии бегут влево / вправо | поле |
| 3 | диагональные линии, угол настраивается | поле |
| 4 | встречные линии: от краёв к центру и обратно | поле |
| 5 | круги расходятся от центра | поле |
| 6 | круги сходятся к центру, пульс | поле |
| 7 | вращающийся луч и спираль | поле |
| 8 | плавные цветовые волны (плазма) | поле |
| 9 | хвост бежит вдоль каждого стика со сдвигом по номеру | по фикстурам |
| 10 | стики заполняются от начала к концу | по фикстурам |
| 11 | стики мягко загораются и гаснут вразнобой | по фикстурам |
| 12 | цвет перетекает по риге: по порядку патча или от точки | по фикстурам |

Общие ручки: скорость (без рывков при смене), ширина, плотность, угол, мягкость краёв
(по умолчанию плавно, синусоидально), точка центра, сдвиг палитры. Переход между режимами —
кроссфейд. Все ручки — параметры tox, их можно привязать снаружи.

## Темп

Генераторам нужен не только BPM, но и фаза — чтобы попадать в долю.

Источники в первой версии: **внутренний BPM**, **TAP** (кнопка), **Ableton Link** (темп из диджейского
софта), **свободная скорость**. При синхронизации скорость задаётся долями: цикл за 1/4, 1/2, 1, 2, 4 доли;
опции — акцент на первую долю такта, смена цвета палитры на долю.

Позже — темп с пульта grandMA2: бит-клок по DMX на 16-битном не-диммерном канале (эффект-«пила»
на такт от спидмастера; Grand Master и Blackout его не гасят), в TD — фаза такта и плавная подстройка.

## Как вставить в патч

- Вход: TOP с видео.
- Параметры tox: файл патча, Active, Master, частота, ArtSync, задержка, сетевая карта,
  режим источника, генератор, источник темпа, открыть редактор, тест-режимы.
- Выходы: превью, пиксели как TOP и CHOP, палитра, info.
- Релизы `dsm.tox` — в GitHub Releases.

## Проверка

- Ядро — pytest вне TD.
- В TD — сверка DMX Map DAT с ожидаемой таблицей адресов, перехват Art-Net/sACN на 127.0.0.1
  байт в байт, замер стоимости кадра. Стенд с железом — в конце этапа.
- Критерии MVP: 100 стиков × 144 px на 8 IP патчатся за 10 минут или быстрее; перехват совпадает
  с таблицей; маппер не дороже 1 мс на кадр при 20 тыс. пикселей, 60 fps.
